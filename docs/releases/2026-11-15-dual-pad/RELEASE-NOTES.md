## 一、两块板怎么区分（调查结论）

1. **3.2.1 为什么一次只能配一块。** 上位机原来通过闭源 `HIDLibrary.dll` 收发。它的 `USBLib_Connect` 按 PID 枚举，`LastDeviceTypeP1 == 0` 时才记录设备、之后同 PID 的设备全部跳过，即每个 PID 只留第一台。两块同固件的板子 PID 相同，第二块永远进不来。
2. **协议层没有可区分的字段。** 两块板的 VID / PID 一样（键盘模式 `4D47:5761`，手柄模式 `4D47:5771`）；`GET_MODE` 回包 `47 mode A2 HVer 03 02` 里 mode 的 bit7 自 V2.12 起由 `DEFAULT_1P2P` 固定置位、UID 固定 `A2`、HVer 同型号同值、FVer 相同。原厂固件名 `5KEY_2P_V2.13` 的 "2P" 指该镜像默认用第二玩家键表（`H K J N M`，`tab_2p`；1P 表是 `W X A D S`），是键位预设，不是双板支持。
3. **USB 序列号每块板不同。** 设备描述符 `iSerialNumber = 3`，字符串由 Artery 库函数 `get_serial_num`（`0x0800A0F8`）上电时从 MCU 唯一 ID（`0x1FFFF7E8 / EC / F0`）生成：UID1+UID3 取 8 位十六进制、UID2 取 4 位，共 12 个字符。它由芯片决定，换 USB 口、换电脑都不变。上位机用 `HidD_GetSerialNumberString` 读到它作为板子身份。
4. **设备路径只作后备。** Windows 的 HID 接口路径 `\\?\hid#vid_4d47&pid_5761&mi_01#7&xxxxxxxx&0&0001#{…}` 中 `7&xxxxxxxx&0` 由所接的集线器端口决定，同一口不变、换口就变。对读不到序列号的设备用它代替。

因此 3.3.0 上位机不再经由 `HIDLibrary.dll` 收发（dll 仍随包分发，里面的枚举类型还在用），自己用 SetupDi 枚举所有 `4D47` 设备、按序列号分组、为每块板打开独立句柄（`PadHid.cs`）。

## 二、1P / 2P 归属规则

每次枚举（启动、插拔、交换）按顺序应用：

1. 已在某栏且仍在线的板子留在原栏。
2. 序列号等于 `Config.ini` `PAD1P=` / `PAD2P=` 的板子回到对应栏——上次会话或「交换 1P/2P」留下的绑定。
3. 其余板子进空栏：原厂第二玩家 PID（`5762 / 5772 / 5763`）优先 2P，否则先 1P 后 2P。两块未知板同时出现时按设备路径排序，接线不变结果就不变。
4. 归属即写回 `PAD1P= / PAD2P=`。

标题栏「交换 1P/2P」把两栏的板子与绑定对调并改写 `Config.ini`。第三块板不分配，标题栏提示「另有 1 块手台已插入但未分配（最多支持两块）」。

## 三、界面与行为

- 主窗口 = 标题栏（主题、语言、交换 1P/2P、「切换为标签页 / 切换为并排」，`DUALVIEW=SIDE|TAB`）+ 两张状态卡 + 两个独立面板。状态卡显示已连接 / 未连接、工作模式、`UID HVer FVer`、序列号；面板保留 3.2.1 的全部功能：灵敏度、调色、延迟释放、按键映射、读取 / 保存设置（含保存后 REBOOT-VERIFY）、读取 / 保存模式、调试模式、固件升级。
- 拔掉一块板只清空该栏，另一栏的句柄、数值和状态不动；重新插回自动回到原栏（规则 1、2）。插拔事件 200 ms 内合并一次重新枚举。
- 一栏保存后等板子重启（最长 12 s）期间，另一栏与「交换」按钮禁用，避免重启中的板子被重新分配。
- 固件升级一次一块：对话框顶部「升级目标」下拉选 1P / 2P（面板按钮预选本栏），显示该板的版本与序列号。点「开始升级」后另一栏锁定并显示「已锁定：另一块板正在升级」，目标栏显示「固件升级中…」。`SET_OTA` 通过所选板子自己的设备路径发送（两块板 VID / PID 相同，不能按 VID / PID 找）。对话框关闭后解锁、重新枚举，目标栏自动核对版本（3.2.1 的 OTA-VERIFY）。
- 救砖：已有一个 Bootloader（`0E8F:8901`）在线时目标可为空栏，直接写入；检测到多于一个 Bootloader 时拒绝开始，提示只保留一块。
- 字号随每栏宽度在 0.7～1.0 之间分档缩放；窗口小于两栏并排时可切到标签页。
- 五键（`KEYCOUNT=5`）与四键共用同一套双板逻辑：固件基线与序列号机制相同，`KEYCOUNT` 只影响面板布局与标题，模拟中按 HVer `13` 的两块板验证通过，未发现五键特有的风险。

## 四、用户操作注意

接线：插主板后置 USB 口；不要用机箱前面板 USB 口（供电常不足、走延长线，会导致设备异常）和无源 HUB；两块板同时使用时如需扩展口，用带独立供电的 HUB。

1. 第一次把两块板一起插上时，哪块是 1P 由规则 3 决定（原厂 2P PID 的板子进 2P，否则按口序）。如果与期望相反，点「交换 1P/2P」，程序会记住，之后不管先插哪块、插哪个口都按序列号回到同一栏。
2. 保存设置、固件升级都是对**本栏**那块板操作；一栏忙时另一栏变灰是正常的，等它结束即可。
3. 升级前确认「升级目标」下拉框选的是想升级的板子。两块板都已经在 Bootloader（都显示 `0E8F:8901`）时程序会拒绝，拔掉一块再试。
4. `Config.ini` 里的 `PAD1P= / PAD2P=` 是序列号绑定，删掉两行即恢复「按口序」分配。
5. 只插一块板时行为与 3.2.1 一致（进 1P，或进它绑定的那一栏）。
6. 出现异常请把 exe 同目录 `PADUEX5.log` 发回：每笔 TX / RX 带 `1P` / `2P` 标签，`USB:` 行列出每次枚举到的板子与归属。

- `xbuild /p:Configuration=Release ConfigApp/HIDDeviceProject.sln`：0 错误（4 条历史警告）。

  - 两块板分别进 1P / 2P，状态卡显示各自的序列号；拔掉 2P 只清空 2P，1P 的数值不变；插回后回到 2P。
