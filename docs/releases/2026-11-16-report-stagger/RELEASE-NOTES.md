## 改了什么

相对 `PADUEX4_V3.2.bin` 差 54 字节，三处：

1. `0x08005E6C`（`App_USB_KBS_SendPacket` 入口）原来的 `push.w {r4-r8,lr}`（`2d e9 f0 41`）换成 `b.w 0x08005DE8`（`ff f7 bc bf`）。
2. `0x08005DE8` 起 50 字节，落在 `Report_Normal` 跳过的原厂 2P 链里（`0x08005DE6` 仍跳到 `0x08005E50`，活代码没动）：

```
08005de8  movw  r2, #0xf7e8
08005dec  movt  r2, #0x1fff          ; 0x1FFFF7E8，MCU 唯一 ID
08005df0  ldr   r3, [r2]             ; UID0
08005df2  ldr.w ip, [r2, #4]         ; UID1
08005df6  eor.w r3, r3, ip
08005dfa  ldr.w ip, [r2, #8]         ; UID2
08005dfe  eor.w r3, r3, ip
08005e02  and   r3, r3, #0xf         ; 0～15
08005e06  cbz   r3, done
08005e08  movs  r2, #48
08005e0a  subs  r2, #1
08005e0c  bne   08005e0a
08005e0e  subs  r3, #1
08005e10  bne   08005e08
08005e12  push.w {r4, r5, r6, r7, r8, lr}
08005e16  b.w   08005e70             ; 回到原函数的第二条指令
```

字节：`4f f2 e8 72 c1 f6 ff 72 13 68 d2 f8 04 c0 83 ea 0c 03 d2 f8 08 c0 83 ea 0c 03 03 f0 0f 03 23 b1 30 22 01 3a fd d1 01 3b fa d1 2d e9 f0 41 00 f0 2b b8`。

3. `0x0800616A` 的 `movs r1,#2`（`02 21`）改为 `movs r1,#3`（`03 21`）。GET_MODE 回 `A2 14 03 03`。

`0x08005E70` 之后的发送函数、bInterval、扫描、释放判断、DTICK、灯效都没有改。`0x14C` 仍是 `0x080084A5`。

每档内层 48 次 `subs/bne`。固件时钟初始化把系统时钟记成 144 MHz，Cortex-M4 上这 48 次是 144 个周期，约 1 µs。Flash 等待会拉长每一档，档与档之间仍是固定倍数。同批次芯片的 UID 低字常常相同，所以用三个字异或，而不是只取 UID0 的低 4 位。

## 预期（有限）

两块板互不知道对方。UID 不同，写键盘 IN 端点之前就差 0～15 档。这是这次补丁全部能保证的事。

不要指望它消除「松开保持 2 ms、松脚后明显滞留」：

- 键盘报告只在键位变化时发一份，不是每 1 ms 填一份。空闲时主机的 IN 令牌得到 NAK。
- 延时加在函数入口，返回后还要等上一份报告被取走（`tx_completed`）。这一等最长约 1 ms，0～15 µs 经常被它吃掉。
- 16 档里约有 1/16 的板对落到同一档。
- 15 µs 相对主机 1 ms 一帧，很少改变报告被取走的那一帧。
- 两块板插在不同的主板根口上时，根本不共用一条 USB 总线。

滞留更符合传感器回落慢、按下和松开共用一个阈值、没有迟滞。那一项不在这个版本里。

## 怎么验证

接线：插主板后置 USB 口；不要用机箱前面板 USB 口（供电常不足、走延长线，会导致设备异常）和无源 HUB；两块板同时使用时如需扩展口，用带独立供电的 HUB。

1. 上位机固件升级选本目录的 `PADUEX4_V3.3.bin`。升级窗口关闭后核对应显示固件 V3.3，左上角 `FVer=V3.3`。五键机不要刷这个文件。
2. 单板手感应与 V3.2 相同：键位、灵敏度、松开保持、灯效都没改。
3. 两块板一起玩。滞留若还在，与这次补丁的预期一致，把现象记下来即可，不必反复重刷。
4. 若要看错开本身：USBPcap 抓键盘 IN 端点（`0x82`），两块板同时改变键位，两次 `usbd` 提交相差若干微秒。看不到这个差，多半是被 1 ms 的完成等待对齐了。
