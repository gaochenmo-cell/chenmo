# 固件 V3.4 / 上位机 3.3.1：松开保持固定为 0（2026-11-17）

两块板一起用时，DTICK = 3 会在阈值附近把保持计数反复重装，表现为卡键；手动设成 0 则正常。这一版把松开保持固定成 0，并且上位机不再提供这一项。

两块板都要刷。只刷一块，另一块仍是旧固件时，旧的那块还会按它自己保存的 DTICK 工作。

接线：插主板后置 USB 口；不要用机箱前面板 USB 口（供电常不足、走延长线，会导致设备异常）和无源 HUB；两块板同时使用时如需扩展口，用带独立供电的 HUB。

## 与 V3.3 的差异

V3.3 只在键盘报告发送前按芯片唯一 ID 忙等 0～15 µs，想把两块板的报告错开。客户实测没有改善。那一版的松开保持仍可调，默认仍是 3。

V3.4 去掉这个错开，代码回到 V3.2，只改松开保持：固定为 0，而且不能再改。

## 相对 V3.2 的字节

四键、五键同一处，各 89 字节。扫描、阈值比较、灯效、改键、灵敏度页、颜色页都不在里面。

| 地址 | 原来 | 现在 |
|---|---|---|
| `0x0800CF24` 起 72 字节 | 36 个 `3` | 36 个 `0`。DTick 页空白或校验失败时的默认表 |
| `0x080064DE..0x080064F4` | 11 条 `nop` | 上电把 `DTick[0..35]` 写成 0。Flash `0x08011000` 里以前保存的值会被加载，然后清掉 |
| `0x08004BDE..0x08004C04` | type 0 / 1 / 2 都写 Flash | type 0、1 照旧。type 2（DTick）不写 Flash，并把刚写入 RAM 的表清 0，然后回 ACK。GET 因此读到 0 |
| `0x0800616A` | `movs r1,#2`（`02 21`） | `movs r1,#4`（`04 21`）。GET_MODE 上报 V3.4。HVer 不动 |

运行时仍是 `Tck[key] = DTick[key]`。表里一直是 0，所以和 V3.2 上手动把 DTICK 设成 0 的报告字节一致。设成 3 时会多保持几毫秒，这一版不会。

## 上位机 3.3.1

在 3.3.0（两块板同时配置）上去掉「延迟释放」页，四键、五键都没有。不再读、不再写 DTick。连上 V3.2 或 V3.3 旧固件也不显示这一项。灵敏度、调色、按键映射、1P / 2P 不动。

用 3.3.0 或更早的上位机去配 V3.4 时，那个输入框还在，但写进去不会生效，读回来是 0。

## 怎么升级

1. 按上面的接线把板子插好。
2. 解压对应的 zip，运行 `PADUEX5.exe`。
3. 固件升级里，四键选 `PADUEX4_V3.4.bin`，五键选 `PADUEX5_V3.4.bin`。两块都刷。
4. 核对 `FVer=V3.4`。手感应与旧固件上手动设 DTICK = 0 相同。

## 回滚

刷回 `PADUEX4_V3.2.bin` / `PADUEX5_V3.2.bin`（SHA-256 `3948c15a6e9c9820c9f7ce9aa8bae331e4c33318961b40c2a9e95aa41a4bdbe5` / `83cb64af023dfa5cc18c9ae02a6d80f849e4fa13e959716df759c5769e4ff2c8`）。刷回之后松开保持恢复为可保存的值，默认 3。3.3.1 上位机没有这一项，要再改数值需要用 3.3.0 或更早的上位机。
