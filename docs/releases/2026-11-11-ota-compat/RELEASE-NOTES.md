## 现象

同一批买的两块五键板，出厂都是 `FVer=2.06`、HVer=13。3.2.1 在同一台电脑上：

- PID 5761 的那块一次成功：37/37 块都回了 `5A A3 FF 00`，OTA-VERIFY 读到 V3.2。
- PID 5771、mode=0x01 的那块：Bootloader `0E8F:8901` 正常，`START(5A A1)` 和 `GETADDR(5A A7)` 都 ACK（地址 `0x08004000`），第一个 1 KB 数据块 8 秒内没有 ACK。有一次第 1 块 ACK 了、第 2 块没有；有一次写到块内偏移 540 时 USB 写被系统取消（`The operation was canceled`）。换线、换到主板后置口仍然这样。板子一直停在 Bootloader，没有变砖。

两块板同批、出厂版本相同，所以「两块板的 Bootloader 版本不一样」权重放低。更值得分清的是下面两件事，它们都只在数据块阶段出现：`START` / `GETADDR` 不擦 APP 区，第一块 `5A A2` + `5A A3` 才是第一次擦写 Flash。

1. **这块板自己的 Flash 擦写**。第一页擦除或编程卡住时，Bootloader 既不回 ACK 也不回 NACK，主机看到的是整段等待一个字节都没有。第 1 块偶尔能 ACK、第 2 块不行，也符合某一页擦写不稳定，而不是命令格式从第一帧就错。
2. **传输节奏**。3.2.1 在等块 ACK 时，每 400 ms 没有回包就关掉 HID 口再重发最后一帧。关口会取消还没完成的读，日志里那句 `The operation was canceled` 就是这个。第一页擦写如果超过 400 ms，ACK 会被这次关口丢掉，看起来和「设备完全不回」一样。成功的那块每块大约 280 ms 就回了，碰不到这条路径。

3.2.1 的日志分不清这两种：超时、非 ACK 帧、读被取消，最后都写成一句 `Data block ACK failed (no ACK)`，而且只留了最后 8 个字节。

## 和最初上位机的差异

最初的升级（控制传输那一版，后来改成中断传输）数据帧已经是 `5A A3` + 2 字节大端长度 + 数据，没有块号、没有帧校验；ACK 是 `5A A3 FF 00`，NACK 是 `5A A3 00 FF`；**每 1 KB 回一次，不是每个 64 字节包回一次**。地址命令 `5A A2`、GETADDR `5A A7` 的 4 字节地址都是大端。这些 3.2.2 都没改。

改过、并且和这次失败对得上的只有节奏：

| 项 | 最初实现 | 3.2.1 | 3.2.2 |
|---|---|---|---|
| 帧间间隔 | 每个数据帧后 2 ms | 1 ms | 正常仍是 1 ms；兼容模式 10 ms，地址命令后再等 20 ms |
| 块 ACK 等待 | 读应答最多约 30 次 × 20 ms，期间不关设备 | 最长 8 s，但每 400 ms 没回包就关口并重发最后一帧 | 正常 8 s、兼容模式 15 s，静默期间不关口、不重发数据帧 |
| 数据帧写失败 | 直接失败 | 3.2.1 起立即中止这一次 | 这一次算失败，整块按 SETADDR 重发，不往已计数的块里补一帧 |
| 块失败后 | 中止 | 中止 | 先 GETADDR；写指针已经越过本块就跳过，否则最多重发 3 次 |
| 结束时的 CRC 命令 `5A A5` | 有 | 没有（成功的那块不需要它） | 仍不发。失败发生在第一块，还走不到这里 |

报告 ID 前缀、Feature 报告都没动：IN=65、OUT=65 时仍然在中断 OUT 前面加 `00`，和成功那块用的是同一条路径。

## 3.2.2 怎么记日志

每一帧收到的原始字节整段写入 `PADUEX5.log`（不再只留 8 字节）：

- `RX ACK`：`5A xx FF 00`
- `RX NACK`：`5A xx 00 FF`
- `RX NON-ACK`：设备有回包，但不是上面两种。后面是整帧十六进制
- `RX SILENCE … no report at all`：等到超时，一个字节都没有
- `RX-ERROR` / `TX … failed`：主机这侧的读写异常，不是设备回了什么

块失败的汇总行是：

```text
OTA: NO ACK block 1/37 @0x08004000 frames=18 send=40 ms wait=8000 ms attempt=0/3 reply=SILENCE
OTA: NO ACK block 1/37 @0x08004000 frames=18 send=40 ms wait=8000 ms attempt=0/3 reply=NON-ACK count=1 last=00 11 22 ...
```

`reply=SILENCE` 是完全不回，`reply=NON-ACK` 是回了非 ACK 帧，`reply=NACK` 是明确拒绝，`reply=TX-FAIL` / `RX-ERROR` 是 USB 传输本身断了。弹窗同样分开写「完全没有回包」和「回了 N 帧但不是 ACK」。

## 请这样升级这块板

1. 解压五键包，运行 `PADUEX5.exe`。点「固件升级」，选**本目录**里的 `PADUEX5_V3.2.bin`。文件信息行应是 V3.2，大小 37072。
2. 先不要勾兼容模式，直接开始。第一块若在 8 秒内没有 ACK，程序会自动勾上兼容模式并提示，然后用更慢的节奏把这一块最多再发 3 次。这段时间不要拔线。也可以在点开始之前就勾上兼容模式。
3. 窗口关掉之后应提示板子上报的版本与文件一致，左上角 `FVer=V3.2`。
4. 若仍然失败，把 `PADUEX5.log` 发回来。看失败那一行的 `reply=`：
   - `SILENCE`：等满了也没有一个字节。更像 Flash 擦写卡住，或 ACK 来得比等待还慢。
   - `NON-ACK` 或 `NACK`：设备有回应但不是确认。把 `last=` 后面的字节一起发来。
   - `TX-FAIL` 或 `RX-ERROR`：USB 传输中断，优先换口再试一次兼容模式。
