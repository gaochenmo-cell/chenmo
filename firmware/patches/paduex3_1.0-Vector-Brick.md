# paduex3_1.0 ～ paduex3_1.5 全部变砖的真正根因：USB 中断向量被覆盖

## 证据

`paduex3_1.0` 把「灵敏度/消抖写 Flash」的补丁代码塞进了 `0x08004130..0x0800415F`，以为那里是空洞。  
那段其实是 **中断向量表**（APP 向量表起于 `0x08004000`，偏移 `0x14C` = IRQ67）。

| 偏移 | IRQ | 原厂 | paduex3_1.0～1.5 |
|------|-----|------|---------------|
| `0x14C` | **67 = OTGFS1（USB）** | `0x080084A5` → `OTGFS1_IRQHandler` | `0x0000BD5B`（垃圾） |
| `0x158` | 70 | `0x0800427B` 默认处理 | `0x20001B5E` |
| `0x15C` | 71 | `0x0800427B` 默认处理 | `0x08011000` |

`0x080084A4` 反汇编：`ldr r0,=otg_core ; bl usbd_irq_handler` —— 就是 USB 中断入口。

## 后果

Bootloader 跳到 APP 后，USB 初始化、D+ 上拉，**第一个 USB 中断就跳进乱码** → 卡死 / HardFault。  
所以：OTA 显示成功，但插上**没有提示音**、上位机找不到。paduex3_1.1 的「无法识别后消失」也是同一原因。

1.3 的栈对齐、1.2 的 boot hook 多写 4 字节是真实的 bug，但即使修了（1.4、1.5）也**还是砖**，因为向量表仍然是坏的。

## 结论

**paduex3_1.0 / 1.1 / 1.2 / 1.3 / 1.4 / 1.5 全部禁止刷入。**

- 向量表 = 原厂  
- 启动序列 = 原厂  
- 无 cave、无改键、无 Flash 写回

```bash
python3 firmware/patches/build_paduex3_1.6.py
```
