# 五键板 5 号口损坏：第 5 键改接到 6～9 号口之一（PADUEX5_P6～P9）

适用：**5 号踏板口硬件损坏的五键板**。第 5 键的键码、灵敏度、颜色、改键、消抖和上位机协议都不变，只把四路传感器和灯带改接到 6、7、8、9 号口中的一个。四个文件各对应一个口，上报版本都是 V3.5，用文件名和 SHA-256 区分。正常板不要刷。

对上位机、游戏和配置表来说它仍然是「第 5 键」：键码 bit4、`Sensi[16..19]`、`Color[16..19]`（含改键槽位 `Color[17]`）、`DTick` 槽位、GET/SET_SENS、RAW 调试流的第 17～20 项，全部不变。

## 为什么不能只改扫描下标

扫描函数 `0x080069CC` 按 `key*4+n` 取 `RAW[36]`（`0x200019F6`）。采样函数 `0x08006E48` 只产生 **20 路**：

| `RAW` 索引 | 来源 | 口 |
|---|---|---|
| 0～15 | 片内 ADC 通道 0～15（PA0～7、PB0～1、PC0～5），`0xFFF - adc` | 口 1～4 |
| 16～19 | 软件 I²C 读寄存器 2，换算 `3915 - min(raw × 0.625, 3915)` | 口 5 |
| 20～35 | 没有任何代码写入 | 口 6～9 |

口 5 的四路不是片内 ADC。采样函数在 `0x08006F78 / 0x08006F84 / 0x08006F90 / 0x08006F9C` 各做一次 `movs r1,#2; movs r0,#地址; bl 0x0800852A`，地址依次是 `0x80 / 0x88 / 0x86 / 0x84`（7 位 `0x40 / 0x44 / 0x43 / 0x42`）。`RAW[20..23]` 没有数据源，改扫描下标读不到 6 号口。

这条 I²C 链只被上述四次调用使用。另一条总线（PB8/PB9，原语从 `0x08008898` 起，读函数 `0x080084C4`）是 100 ms 一次的电源监测，本补丁不动它。

## 6～9 号口的脚是怎么推定的

板级 GPIO 初始化 `0x08007E4C..0x0800846A` 把六对脚配成与口 5 相同的开漏输出，顺序是：

```
PB8 PB9 | PC11 PC12 | PB3 PB4 | PF6 PF7 | PB10 PB11 | PB2 PA10
```

前两对已经能对上：PB8/PB9 是电源监测，PC11/PC12 是口 5（代码里 `0x800` = PC11 当 SCL，`0x1000` = PC12 当 SDA，初始化也是 SCL 在前）。后面四对按同样的规则（先初始化的那根当 SCL）推定为口 6～9。九条踏板灯带里，PB14 / PB15 / PC6 / PC7 / PC8 已确认为 K1～K5，剩下 PC9、PA8、PB13、PB12 按同样的顺序推定为 LED6～LED9。

`0x0800847C` 在进入主循环之前把 SWJTAG 设为 `0x30100302` 的 bit16 宽 3 取值 2（关 JTAG、留 SWD），PB3/PB4 那时已经是 GPIO。USB 是 PA11/PA12，不占用 PB10/PB11。PF4/PF5 是 12 V 检测输入，PF6/PF7 只在这次初始化里出现。PA10 在初始化里配成 GPIO 输出，没有复用到 USART。

这是从初始化顺序推出来的，固件里没有 6～9 号口的地址表，也没有任何对传感器配置寄存器的写。口 5 的芯片只被读寄存器 2。上一版把第 5 键固定接到 PB3/PB4 + PC9、地址仍是 `0x80/0x88/0x86/0x84`，真机上 1～4 号口正常、6 号口没有反应，所以「第几对脚 = 几号口」这一条没有被证实，四份镜像是同一推断各移一对脚。

| 文件 | SCL | SDA | 灯 | 把握 |
|---|---|---|---|---|
| `PADUEX5_P6_V3.5.bin` | PB3 | PB4 | PC9 | 偏低。上一版已经刷过这一对脚。本版只多了地址探测，先刷它是为了排除「脚是对的、地址不是口 5 那一组」 |
| `PADUEX5_P7_V3.5.bin` | PF6 | PF7 | PA8 | 中等。时钟位是 APB2 的 bit 7，板级初始化已经打开；PF6/PF7 没有别的用途 |
| `PADUEX5_P8_V3.5.bin` | PB10 | PB11 | PB13 | 中等。不碰 USB，也不碰 SWD |
| `PADUEX5_P9_V3.5.bin` | PB2 | PA10 | PB12 | 偏低。两根脚不在同一个 GPIO 口，极性最没有旁证 |

丝印上的口号是否等于这个初始化顺序，固件不能证明。四份都试过仍没有读数时，下一步是对调该口的 SCL/SDA，而不是再猜别的脚。

## 这一版怎么接这些脚

`firmware/patches/build_paduex5_px_v3.5.py` 以 `PADUEX5_V3.2.bin` 为底，无参数时出四份，也可以只给一个口号。每份镜像里 SCL、SDA 的端口和引脚是编进去的常量，所以口 9（PB2 与 PA10 分属 GPIOB、GPIOA）和另外三口共用同一段位操作代码。

口 5 原来的位操作链 `0x0800852A..0x08008897` 整段换掉，`0x08008898` 起的电源监测总线逐字节保留。布局：

| 位置 | 作用 |
|---|---|
| `0x0800852A` | `b.w read16`。采样函数原来的 `bl 0x0800852A` 不动，`b.w` 不改 LR |
| `0x0800852E` | `b.w slot_setup` |
| `0x08005DE8` 起 4×6 字节 | `movs r2,#槽号; b.w slot_setup`。这段位于 `0x08005DE6` 的跳转之后、`0x08005E50` 之前，原来执行不到 |
| `0x08006F78 / 84 / 90 / 9C` | 原来的 `movs r1,#2; movs r0,#地址` 换成 `bl` 到对应的 6 字节入口，后面的 `bl 0x0800852A` 保留 |
| 灯带 `0x080071DC / F0 / 20C / 220` 的 `mov.w r1`，以及 `0x08007208 / 0x08007238` 的端口字面量 | 只改第 5 键那条灯带 |
| `0x0800616A` | `movs r1,#5`。HVer `0x0800615E` 仍是 `0x13`，主版本不动。四份镜像都回 `47 mode A2 13 03 05` |

`slot_setup` 保存采样函数的 r4（缓冲区）和 r7（浮点常量），跑一次地址探测，再按槽号取出 8 位地址、把 r1 设为 2，返回到原来的 `bl read16`。

### 上电地址探测

探测结果放在初始栈（`0x20002A20`）之上、没有任何字面量引用的 `0x20007F00`：

| 地址 | 内容 |
|---|---|
| `0x20007F00` | 魔数 `0xA55A5AA5`。SRAM 上电是随机的，单字节标志不可靠 |
| `0x20007F04` | 应答的芯片个数 |
| `0x20007F08` | 四个 8 位写地址 |

只在魔数不符时探测一次，顺序是口 5 那一组优先，然后其余偶数地址：

```
0x80 0x88 0x86 0x84  0x82 0x8A 0x8C 0x8E  0x90 0x92 0x94 0x96  0x98 0x9A 0x9C 0x9E
```

每个地址只做 START、写一字节、STOP。应答就按发现顺序记下，满 4 个停止。一个都没有时，`read16` 直接返回 `0xFFFF`，换算结果是 0，第 5 键保持松开，RAW 柱停在 0。这样插错口不会像上一版那样从上电起就把第 5 键按死（上一版无应答时返回 0，换算成 3915）。

只找到 1～3 个时，空槽用口 5 的地址补上，个数仍记实际应答数。空槽的读会无应答并换成 3915，可能看起来像有一路被按住。踏板线上是四颗芯片时不会走到这里。

读寄存器的时序与口 5 相同：START、写地址、写寄存器号、重复 START、写地址|1、读两字节（第一字节 ACK、第二字节 NACK）、STOP。无应答则 STOP 并返回 0。采样 SDA 之前把该脚改成输入上拉（CRL 半字节 `0x8`，同时置位），从机才能把线拉低；输出高电平会挡住应答。

## 构建与验证

```bash
python3 firmware/patches/build_paduex5_px_v3.5.py          # 四份都出
python3 firmware/patches/build_paduex5_px_v3.5.py 9        # 只出口 9
python3 firmware/tests/emu_port6_remap.py firmware/PADUEX5_P6_V3.5.bin
python3 firmware/tests/emu_port6_remap.py firmware/PADUEX5_V3.2.bin
```

构建脚本断言：引擎停在 `0x08008898` 之前、两处入口都是 `b.w`、调用点原来是 `02 21 imm 20`、`0x08005DE6` 的跳转和 `0x08008898` 起的 8 字节未改、所有差异只落在入口 / 引擎 / 四个调用点 / 灯带常量 / 版本字节、`0x14C == 0x080084A5`、体积 37072。

`emu_port6_remap.py` 在口 5～9 各挂一条位级从机，执行真实的采样、扫描和刷灯。四份镜像以及 V3.2 对照都通过，覆盖：

- 口 5 的地址顺序 `0x80/0x88/0x86/0x84`，换算 `0 / 0x800 / 0x1000 / 0x1F00 → 3915 / 2635 / 1355 / 0`，其余口没有 START
- 第二次采样不再探测
- 非口 5 的地址 `0x82/0x8A/0x8E/0x94` 仍按发现顺序换算，踩下得到键码 `0x10`
- 一个芯片都不应答时 RAW 为 0、键码为 0、扫描能返回，1 号口仍能按下和松开
- 踩目标口 → 键码 `0x10`、灯只在该口的灯脚上；踩另外四个口无键码无灯；K1～K4 与和弦不变

`emu_set_sens`、`emu_report_normal`、`emu_keymap_e2e`、`emu_keyscan_paduex4`、`emu_get_mode` 在 P6 和 P9 上通过。P7、P8 的 GET_MODE 回包同为 `47 mode A2 13 03 05`。
